# 数据库架构总览 / Database Architecture Overview

## 概述 / Overview

pinpet-server-v2 使用 **三个独立的 RocksDB 实例** 来分离不同类型的数据，提高性能和可维护性。

pinpet-server-v2 uses **three separate RocksDB instances** to separate different types of data, improving performance and maintainability.

---

## 数据库实例 / Database Instances

### 1. 事件数据库 / Event Database

**路径 / Path:**
- 默认位置 / Default location: `./data/event`
- 配置项 / Config key: `database.rocksdb_path`

**主要功能 / Main Functions:**
- 存储区块链事件原始数据
- 存储 Token 元数据和索引
- 提供事件历史查询

**存储内容 / Storage Content:**

| 数据类型 | 键前缀 | 说明 |
|---------|--------|------|
| 区块链事件 | `event:` | TokenCreated、BuySell、LongShort、FullClose 等 |
| Mint索引 | `idx_mint:` | 按代币查询事件 |
| User索引 | `idx_user:` | 按用户查询事件 |
| User TC专用索引 | `idx_user_tc:` | 按用户查询TokenCreated事件 |
| 签名映射 | `sig_map:` | 按交易签名查询事件 |
| Slot批量索引 | `slot_batch:` | 按区块高度查询事件 |
| Token主数据 | `token:` | 代币详情信息 |
| Token Symbol索引 | `token_symbol:` | 按Symbol查询代币 |
| Token创建时间索引 | `token_created:` | 按创建时间查询代币 |
| Token Slot索引 | `token_slot:` | 按Slot查询代币 |
| Token创建者索引 | `token_payer:` | 按创建者查询代币 |

### 2. 统计数据库 / Statistics Database

**路径 / Path:**
- 默认位置 / Default location: `./data/stats`
- 配置项 / Config key: `database.stats_db_path`

**主要功能 / Main Functions:**
- 存储聚合统计数据
- 存储K线数据
- 提供排序索引支持 Top K 查询

**存储内容 / Storage Content:**

| 数据类型 | 键前缀 | 说明 |
|---------|--------|------|
| K线数据 | `kline:` | s1/s30/m5 三种时间间隔 |
| K线Mint索引 | `kline_index:mint:` | 按Mint查询K线 |
| K线时间索引 | `kline_index:time:` | 按时间范围查询K线 |
| K线元数据 | `kline_meta:` | 统计和配置元数据 |
| 交易额数据 | `vol:` | 6个时间周期的交易额 |
| 交易额排序索引 | `vol_rank:` | 支持交易额榜查询 |
| 钱包数数据 | `markets:` | 周期内唯一钱包数 |
| 钱包数排序索引 | `markets_rank:` | 支持活跃度榜查询 |
| 绝对钱包数数据 | `markets_abs:` | 全局唯一钱包数 |
| 绝对钱包数周期索引 | `markets_abs_period:` | 周期累计数据 |
| 绝对钱包数排序索引 | `markets_abs_rank:` | 支持全局钱包榜查询 |
| 涨跌幅数据 | `change:` | 6个时间周期的涨跌幅 |
| 涨跌幅排序索引 | `change_rank:` | 支持涨跌榜查询 |

### 3. OrderBook数据库 / OrderBook Database

**路径 / Path:**
- 默认位置 / Default location: `./data/orderbook`
- 配置项 / Config key: `database.orderbook_db_path`

**主要功能 / Main Functions:**
- 存储订单簿数据
- 存储订单簿快照
- 支持订单同步和验证

**存储内容 / Storage Content:**

| 数据类型 | 键前缀 | 说明 |
|---------|--------|------|
| 订单数据 | `order:` | 单个订单详情 |
| 订单簿索引 | (待补充) | 订单簿查询索引 |

**性能优化配置 / Performance Optimization:**
- 单个写缓冲区大小 / Write buffer size: 256 MB (可配置)
- 最大写缓冲区数量 / Max write buffers: 4 (可配置)
- 禁用 fsync / Disable fsync: 提高写入性能
- 后台任务数 / Background jobs: 8 (可配置)

## 数据库分离的优势 / Benefits of Database Separation

### 1. 性能隔离 / Performance Isolation
- 事件写入不影响统计查询性能
- OrderBook 高频写入独立优化
- 各数据库可独立调优参数

### 2. 存储管理 / Storage Management
- 可针对不同数据类型设置不同的保留策略
- 独立备份和恢复
- 磁盘空间独立管理

### 3. 可维护性 / Maintainability
- 清晰的数据边界
- 独立的升级和迁移
- 故障隔离

## 数据流向 / Data Flow

```
区块链事件 (Blockchain Events)
    ↓
事件监听器 (Event Listener)
    ↓
    ├─→ 事件数据库 (Event DB)
    │   ├─ 原始事件数据
    │   └─ Token 元数据
    │
    ├─→ 统计数据库 (Stats DB)
    │   ├─ K线聚合
    │   ├─ 交易额统计
    │   ├─ 涨跌幅计算
    │   └─ 钱包数统计
    │
    └─→ OrderBook数据库 (OrderBook DB)
        ├─ 订单创建/更新
        ├─ 订单平仓
        └─ 订单簿快照
```

## 配置示例 / Configuration Example

```toml
[database]
# 事件数据库路径 / Event database path
rocksdb_path = "./data/event"

# OrderBook数据库路径 / OrderBook database path
orderbook_db_path = "./data/orderbook"

# 统计数据库路径 / Statistics database path
stats_db_path = "./data/stats"

# OrderBook数据库性能配置 / OrderBook database performance config
[database.orderbook_db]
write_buffer_size_mb = 256
max_write_buffer_number = 4
use_fsync = false
paranoid_checks = false
max_background_jobs = 8
```

## 磁盘空间估算 / Disk Space Estimation

### 典型场景（1百万事件） / Typical Scenario (1M Events)

| 数据库 | 原始数据 | 索引 | 总计（压缩后） | 占比 |
|-------|---------|------|--------------|------|
| 事件数据库 | 1-2 GB | 300 MB | 800 MB - 1.5 GB | 50% |
| 统计数据库 | 200-400 MB | 50 MB | 150-250 MB | 15% |
| OrderBook数据库 | 500-800 MB | 100 MB | 400-600 MB | 35% |
| **总计** | - | - | **1.35-2.35 GB** | **100%** |

**注意 / Notes:**
- 以上数据基于 LZ4/Zstd 压缩
- 实际大小取决于事件类型分布
- K线数据会随时间增长（可设置保留策略）

## 备份策略 / Backup Strategy

### 全量备份 / Full Backup
```bash
# 停止服务 / Stop service
systemctl stop pinpet-server

# 备份所有数据库 / Backup all databases
tar -czf backup_$(date +%Y%m%d).tar.gz ./data/

# 重启服务 / Restart service
systemctl start pinpet-server
```

### 增量备份 / Incremental Backup
- RocksDB 支持 Checkpoint 快照
- 每个数据库可独立创建快照
- 建议每日备份统计数据库，每周备份事件数据库

---

## 故障恢复 / Disaster Recovery

### 单数据库损坏 / Single Database Corruption
1. 停止服务 / Stop service
2. 删除损坏的数据库目录 / Remove corrupted database directory
3. 从备份恢复 / Restore from backup
4. 重启服务 / Restart service

### 统计数据重建 / Rebuild Statistics
如果统计数据库损坏但事件数据库完好：
1. 删除统计数据库 / Remove stats database
2. 从事件数据库重新聚合 / Re-aggregate from event database
3. 重建K线和统计指标 / Rebuild K-lines and statistics

## 最佳实践 / Best Practices

### 1. 性能优化 / Performance Optimization
- 为每个数据库设置独立的磁盘（如使用SSD）
- 根据负载调整写缓冲区大小
- 定期清理过期数据

### 2. 数据一致性 / Data Consistency
- 使用 WriteBatch 确保原子写入
- 定期验证索引完整性
- 监控数据库健康状态

### 3. 容量规划 / Capacity Planning
- 预估每日数据增长量
- 设置合理的数据保留策略
- 预留至少 30% 的磁盘空间
