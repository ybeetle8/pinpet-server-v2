# 升级方案 - 第一阶段：动态流动池（简化版）

## 一、升级目标

**核心目标**：将虚拟流动池的初始大小从硬编码常量改为池子的动态参数

### 当前问题
- `INITIAL_SOL_RESERVE_DECIMAL` 和 `INITIAL_TOKEN_RESERVE_DECIMAL` 是硬编码常量
- 所有池子都使用相同的 k 值（30 * 1073000000）
- 无法为不同代币创建不同初始流动性规模的池子

### 升级后效果
- 每个池子存储自己的初始虚拟储备量参数（`initial_virtual_sol` 和 `initial_virtual_token`）
- `curve_amm.rs` 根据池子的初始参数计算 k 值
- 所有计算函数接收池子参数作为输入

### 重要说明
- ⚠️ **不考虑向后兼容**：合约会重新部署，不需要处理旧池子
- ⚠️ **不使用默认常量**：创币时直接写死初始值
- ⚠️ **直接修改函数签名**：不创建 `_with_params` 版本，直接在原函数上加参数

## 二、核心概念理解

### 2.1 两种储备量字段的区别

```rust
pub struct BorrowingBondingCurve {
    // ========== 动态储备量（交易时会变化） ==========
    pub lp_sol_reserve: u64,      // 当前实际 SOL 储备量
    pub lp_token_reserve: u64,    // 当前实际 Token 储备量

    // ========== 初始虚拟储备量（创建后固定不变） ==========
    pub initial_virtual_sol: u64,     // 初始虚拟 SOL（用于计算 k 值）
    pub initial_virtual_token: u64,   // 初始虚拟 Token（用于计算 k 值）
}
```

**关键区别**：

| 字段 | 用途 | 是否变化 | 示例值 |
|------|------|----------|--------|
| `lp_sol_reserve` | 当前实际流动性 | 交易时动态变化 | 初始 30 SOL，交易后可能变为 35 SOL |
| `lp_token_reserve` | 当前实际流动性 | 交易时动态变化 | 初始 10.73亿，交易后可能变为 10亿 |
| `initial_virtual_sol` | 计算 k 值的固定参数 | 创建后永不改变 | 始终保持 30 SOL |
| `initial_virtual_token` | 计算 k 值的固定参数 | 创建后永不改变 | 始终保持 10.73亿 |

**⚠️ 重要**：`curve_amm.rs` 中所有计算**必须使用** `initial_virtual_*` 字段，**不能使用** `lp_*_reserve` 字段！

### 2.2 为什么使用 u64 存储？

- SOL 储备量：用 lamports 表示（9位精度），范围 10^9 ~ 10^12，u64 足够
- Token 储备量：用最小单位表示（9位精度），范围 10^17 ~ 10^19，u64 足够
- 节省存储空间（相比 u128 节省一半）

```rust
/// 根据初始储备量计算 k 值（Decimal 版本）
///
/// # 参数
/// * `initial_virtual_sol` - 初始虚拟SOL储备量 (lamports, 9位精度)
/// * `initial_virtual_token` - 初始虚拟Token储备量 (最小单位, 9位精度)
///
/// # 返回值
/// * `Option<Decimal>` - 成功返回 k 值，失败返回 None
///
/// # 计算公式
/// k = (sol / 10^9) * (token / 10^9)
#[inline(always)]
pub fn calculate_k_from_reserves(
    initial_virtual_sol: u64,
    initial_virtual_token: u64,
) -> Option<Decimal> {
    // 转换为 Decimal
    let sol_decimal = Self::u64_to_sol_decimal(initial_virtual_sol)?;
    let token_decimal = Self::u64_to_token_decimal(initial_virtual_token)?;

    // 计算 k = sol * token
    sol_decimal.checked_mul(token_decimal)
}
```

## 四、错误处理

### k 值计算失败处理

根据确认，k 值计算失败时**直接报错**，不使用默认值或其他降级方案。

#### 在 `curve_amm.rs` 中

```rust
pub fn calculate_k_from_reserves(
    initial_virtual_sol: u64,
    initial_virtual_token: u64,
) -> Option<Decimal> {
    let sol_decimal = Self::u64_to_sol_decimal(initial_virtual_sol)?;
    let token_decimal = Self::u64_to_token_decimal(initial_virtual_token)?;

    // 如果计算失败，返回 None（调用方会转换为错误）
    sol_decimal.checked_mul(token_decimal)
}
```

#### 在调用方（如 `buy_sell.rs`）

```rust

    ctx.accounts.curve_account.initial_virtual_sol,
    ctx.accounts.curve_account.initial_virtual_token,
    ctx.accounts.curve_account.price,
)
.ok_or(ErrorCode::ReserveCalculationError)?;  // ← 直接转换为错误并返回
```
