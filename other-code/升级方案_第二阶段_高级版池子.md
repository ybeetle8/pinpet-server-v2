# 升级方案 - 第二阶段：高级版池子

## 🎯 核心设计决策

### 关键改进：使用 Option 参数，无需 pool_version

**函数签名**：
```rust
pub fn create_token(
    ctx: Context<CreateToken>,
    name: String,
    symbol: String,
    uri: String,
    // 新增可选参数（全部使用 Option 类型）
    custom_lp_sol: Option<u64>,         // 自定义流动池SOL数量
    custom_lp_token: Option<u64>,       // 自定义流动池Token数量
    custom_borrow_ratio: Option<u8>,    // 自定义借贷池比例 (5-30%)
    custom_borrow_duration: Option<u32>, // 自定义借贷时长 (3天-6个月，单位：秒)
) -> Result<()>
```

**设计要点**：
- ✅ **无需 `pool_version` 参数**：通过检查四个 Option 参数是否都为 None 来自动判断池子类型
- ✅ **全 None = 普通版**：`(None, None, None, None)` → 使用默认参数，支持手续费减半
- ✅ **任一 Some = 高级版**：必须四个参数都提供（否则报错），手续费永不减半
- ✅ **向后兼容**：前端传入 `(null, null, null, null)` 等价于第一阶段的默认行为
- ✅ **手续费折扣机制**：在 `apply_fee_discount_if_needed!` 宏内部添加池子类型检查，所有调用点自动生效

## 一、升级目标

**核心目标**：在第一阶段动态流动池的基础上，增加高级版池子功能，支持自定义初始流动池和借贷池参数

### 与第一阶段的关系
- **第一阶段（已完成）**：实现了动态流动池，但使用固定默认值（30 SOL + 10.73亿 Token）
- **第二阶段（本阶段）**：允许创建代币时自定义初始流动池参数，并引入普通版/高级版的区分

### 升级后效果
- 创建代币时可以选择：
  - **普通版（pool_type=0）**：使用默认参数，享受价格里程碑手续费减半
  - **高级版（pool_type=1）**：自定义初始流动池和借贷参数，手续费永不减半
- 高级版用户可以控制：
  - 初始虚拟 SOL 和 Token 数量（在限定范围内）
  - 借贷池代币占比（5%-30% 可选）
  - 借贷时长（3天-6个月 可选）

## 二、核心概念

### 2.1 池子类型

| 池子类型 | pool_type | 初始流动池 | 借贷池比例 | 借贷时长 | 手续费减半 |
|---------|-----------|------------|------------|----------|------------|
| **普通版** | 0 | 默认值（30 SOL + 10.73亿 Token） | 固定 20% | 使用 Params.base_borrow_duration | ✅ 支持（基于价格里程碑） |
| **高级版** | 1 | 自定义（范围内可选） | 5%-30% 可选 | 3天-6个月 可选 | ❌ 永不减半 |

**⚠️ 重要说明：借贷时长参数来源的区别**
- **普通版**：使用 `ctx.accounts.params.base_borrow_duration`（来自 Params PDA 账户，由管理员配置）
- **高级版**：使用创建时传入的 `custom_borrow_duration` 值（在 3天-6个月 范围内）
- 这与其他参数不同：SOL、Token、Ratio 参数的普通版使用常量，而 borrow_duration 使用 Params 账户值

### 2.2 初始流动池参数限制

为防止极端值导致计算问题或流动性失衡，需要设置合理的上下限：

```rust
// 初始虚拟SOL限制 (lamports, 9位精度)
pub const MIN_INITIAL_VIRTUAL_SOL: u64 = 10_000_000_000;      // 10 SOL
pub const MAX_INITIAL_VIRTUAL_SOL: u64 = 1_000_000_000_000;   // 1,000 SOL
pub const DEFAULT_INITIAL_VIRTUAL_SOL: u64 = 30_000_000_000;  // 30 SOL (普通版默认)

// 初始虚拟Token限制 (最小单位, 9位精度)
pub const MIN_INITIAL_VIRTUAL_TOKEN: u64 = 100_000_000_000_000_000;        // 1亿 Token
pub const MAX_INITIAL_VIRTUAL_TOKEN: u64 = 10_000_000_000_000_000_000;     // 100亿 Token
pub const DEFAULT_INITIAL_VIRTUAL_TOKEN: u64 = 1_073_000_000_000_000_000;  // 10.73亿 Token (普通版默认)

// 借贷池代币占比限制 (相对于总铸造量的百分比，基数100)
pub const MIN_BORROW_POOL_RATIO: u8 = 5;   // 5%
pub const MAX_BORROW_POOL_RATIO: u8 = 30;  // 30%
pub const DEFAULT_BORROW_POOL_RATIO: u8 = 20; // 20% (普通版默认)

// 借贷时长限制 (单位：秒)
pub const MIN_BORROW_DURATION: u32 = 259_200;      // 3天 (3 * 24 * 3600)
pub const MAX_BORROW_DURATION: u32 = 15_552_000;   // 6个月 (180 * 24 * 3600)
pub const DEFAULT_BORROW_DURATION: u32 = 2_592_000; // 30天 (30 * 24 * 3600，普通版默认)
```

**限制说明**：
1. **SOL 范围（10-1000）**：
   - 太小（<10）：初始价格太高，不利于交易
   - 太大（>1000）：需要创建者投入过多 SOL，不实用

2. **Token 范围（1亿-100亿）**：
   - 太小（<1亿）：代币单位过于稀缺，流动性不足
   - 太大（>100亿）：可能接近 u64 上限，有溢出风险

3. **借贷池比例（5%-30%）**：
   - 太小（<5%）：可开杠杆仓位太少，功能受限
   - 太大（>30%）：流动池代币不足，影响现货交易

4. **借贷时长（3天-6个月）**：
   - 太短（<3天）：用户来不及管理仓位，容易被强制清算
   - 太长（>6个月）：资金占用时间过长，流动性风险增加
   - 注意：常量中的 `MAX_BORROW_DURATION` 需要从 30天 更新为 6个月

### 2.3 代币分配计算

创建代币时，总铸造量分为三部分：

```
总铸造量 = 流动池代币 + 借贷池代币 + 预留代币
```

**示例（普通版，借贷池比例20%）**：
```
流动池代币: 1,073,000,000,000,000,000  (10.73亿, 9位精度)
借贷池代币: 214,600,000,000,000,000    (2.146亿, 9位精度) = 流动池 * 20%
总铸造量:   1,287,600,000,000,000,000  (12.876亿, 9位精度)
```

**计算公式（高级版）**：
```rust
// 用户指定 initial_virtual_token 和 borrow_pool_ratio
let lp_token_amount = initial_virtual_token;
let borrow_token_amount = lp_token_amount
    .checked_mul(borrow_pool_ratio as u64)
    .ok_or(...)?
    .checked_div(100)
    .ok_or(...)?;
let total_supply = lp_token_amount + borrow_token_amount;
```

### 3.4 修改 `create_token` 函数实现

**文件**：[programs/pinpet/src/instructions/create_token.rs](../programs/pinpet/src/instructions/create_token.rs)

#### 3.4.1 参数验证和归一化（在函数开始处添加）

在现有参数验证后（约第 65 行之后），添加新参数的验证和归一化：

```rust
    // ======== 新增：高级版池子参数验证和归一化 ========

    // 判断池子类型：如果四个 Option 参数都为 None，则为普通版；否则为高级版
    let is_advanced_pool = custom_lp_sol.is_some()
        || custom_lp_token.is_some()
        || custom_borrow_ratio.is_some()
        || custom_borrow_duration.is_some();

    // 归一化参数：根据池子类型设置实际使用的值
    let (
        actual_pool_type,
        actual_initial_virtual_sol,
        actual_initial_virtual_token,
        actual_borrow_pool_ratio,
        actual_borrow_duration,
        actual_lp_token_amount,
        actual_borrow_token_amount,
    ) = if is_advanced_pool {
        // ========== 高级版池子 ==========

        // 验证：四个参数必须同时提供（不能只提供部分参数）
        require!(
            custom_lp_sol.is_some()
                && custom_lp_token.is_some()
                && custom_borrow_ratio.is_some()
                && custom_borrow_duration.is_some(),
            ErrorCode::IncompleteAdvancedPoolParams
        );

        // 解包参数
        let sol_value = custom_lp_sol.unwrap();
        let token_value = custom_lp_token.unwrap();
        let ratio_value = custom_borrow_ratio.unwrap();
        let duration_value = custom_borrow_duration.unwrap();

        // 验证：custom_lp_sol 在有效范围内
        require!(
            sol_value >= crate::constants::MIN_INITIAL_VIRTUAL_SOL
                && sol_value <= crate::constants::MAX_INITIAL_VIRTUAL_SOL,
            ErrorCode::InvalidInitialVirtualSol
        );

        // 验证：custom_lp_token 在有效范围内
        require!(
            token_value >= crate::constants::MIN_INITIAL_VIRTUAL_TOKEN
                && token_value <= crate::constants::MAX_INITIAL_VIRTUAL_TOKEN,
            ErrorCode::InvalidInitialVirtualToken
        );

        // 验证：custom_borrow_ratio 在有效范围内
        require!(
            ratio_value >= crate::constants::MIN_BORROW_POOL_RATIO
                && ratio_value <= crate::constants::MAX_BORROW_POOL_RATIO,
            ErrorCode::InvalidBorrowPoolRatio
        );

        // 验证：custom_borrow_duration 在有效范围内
        require!(
            duration_value >= crate::constants::MIN_BORROW_DURATION
                && duration_value <= crate::constants::MAX_BORROW_DURATION,
            ErrorCode::InvalidBorrowDuration
        );

        // 计算流动池和借贷池代币数量
        let lp_token = token_value;
        let borrow_token = lp_token
            .checked_mul(ratio_value as u64)
            .ok_or(ErrorCode::BorrowTokenCalculationOverflow)?
            .checked_div(100)
            .ok_or(ErrorCode::BorrowTokenCalculationOverflow)?;

        // 验证：借贷池代币数量不能为 0
        require!(
            borrow_token > 0,
            ErrorCode::BorrowTokenAmountZero
        );

        (
            crate::constants::POOL_TYPE_ADVANCED,
            sol_value,
            token_value,
            ratio_value,
            duration_value,
            lp_token,
            borrow_token,
        )
    } else {
        // ========== 普通版池子（使用默认值） ==========
        // 注意：普通版的借贷时长使用 Params.base_borrow_duration（来自Params账户）
        // 而不是 DEFAULT_BORROW_DURATION 常量，这与其他参数不同
        (
            crate::constants::POOL_TYPE_STANDARD,
            crate::constants::DEFAULT_INITIAL_VIRTUAL_SOL,
            crate::constants::DEFAULT_INITIAL_VIRTUAL_TOKEN,
            crate::constants::DEFAULT_BORROW_POOL_RATIO,
            ctx.accounts.params.base_borrow_duration,  // ← 使用 Params 账户的值，而非常量
            crate::constants::STANDARD_LP_TOKEN_RESERVE,
            crate::constants::STANDARD_BORROW_TOKEN_RESERVE,
        )
    };

    msg!("创建池子类型: {}", if actual_pool_type == 0 { "普通版" } else { "高级版" });
    msg!("初始虚拟SOL: {} lamports", actual_initial_virtual_sol);
    msg!("初始虚拟Token: {}", actual_initial_virtual_token);
    msg!("借贷池占比: {}%", actual_borrow_pool_ratio);
    msg!("借贷时长: {} 秒 ({} 天)", actual_borrow_duration, actual_borrow_duration / 86400);
    msg!("流动池代币数量: {}", actual_lp_token_amount);
    msg!("借贷池代币数量: {}", actual_borrow_token_amount);
```

        use crate::constants::*;

        let flag = $ctx.accounts.curve_account.fee_discount_flag;

        if (flag == FEE_DISCOUNT_FLAG_INITIAL && price > PRICE_THRESHOLD_10X)
